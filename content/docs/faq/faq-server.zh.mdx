## Webhook

| 项目     | 问题                           | 解答                                                                                                                                                                                                                          |
| -------- | ------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 重试逻辑 | webhook 发送失败会自动重试吗？ | 最初以 1 分钟间隔重试 3 次；<br />随后以 10 分钟间隔重试 3 次                                                                                                                                                                 |
| 配置维度 | 是否可按门店配置不同的 URL？   | 配置以“应用”为单位；请根据 webhook 通知中的 locationId 判断门店。                                                                                                                                                             |
| 通知类型 | 支付失败时会发送通知吗？       | 支付失败不发送 webhook 通知。<br />使用 charge 时，请在服务端通过轮询确认支付状态，若变为失败，建议设计为可再次发起支付。<br />使用 EasyQR 时，若在码的有效期内失败，用户可重新选择支付方式再次支付；因此建议等待至有效期结束 |
| 生效时间 | 在管理后台保存后是否立即生效？ | 是，立即生效。<br />支持配置多条，完成切换后建议删除旧 URL                                                                                                                                                                    |

## frontUrl

| 关键词     | 问题                                                                | 解答                                                                                                 |
| ---------- | ------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| 浏览器标签 | 支付完成后跳转到 frontUrl 时，从原标签页打开还是新标签页？          | 信用卡：从原标签页跳转。<br />若为条码/二维码等需唤起 App 的场景：跳转到 frontUrl 时将在新标签页打开 |
| 隐私模式   | 在隐私/无痕模式下能否正常跳转到 frontUrl？                          | 可以，在隐私模式下也能正常跳转。                                                                     |
| 跳转端     | frontUrl 的跳转发生在商户展示二维码的页面，还是用户支付后的手机端？ | 跳转发生在访问 code URL 的设备上，因此会在用户的手机端跳转                                           |
| 跳转条件   | 只有使用 checkout 才会跳转吗？                                      | 跳转由访问 codeUrl 触发，因此仅使用 Code API 也会跳转                                                |

## charge

| 关键词      | 问题                       | 解答                                                                                                                                                                                                                                             |
| ----------- | -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 预授权/入账 | 预授权与入账可否分时处理？ | 信用卡与 Apple Pay/Google Pay 均可。<br />【实现方式】<br />在 create charge 中设置 capture=false 获取预授权。<br />通过 capture charge 完成入账。<br />【注意事项】<br />信用卡/Google Pay 仅支持等额或减额入账。<br />Apple Pay 仅支持等额入账 |

## EasyQR

| 关键词  | 问题                              | 解答                                                                                                                                                                                                                                                                                                                           |
| ------- | --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| orderNo | orderNo 可以重复吗？              | 在同一应用内必须保持 orderNo 唯一。                                                                                                                                                                                                                                                                                            |
|         | 重复的 orderNo 会返回什么错误码？ | 当前行为：<br />对于已完成的交易，或在码生成后且仍在有效期内，使用相同 orderNo 重新生成时，将返回以下错误：<br />`"code": "9_000_000_40022",`<br />`"errorCode": "M002007",`<br />`"message": "該当注文番号はすでに支払済み。"`<br />因此，可使用因 Close EasyQR 取消的交易，或因有效期到期而取消的交易所用的 orderNo 重新创建 |

## API 密钥

| 关键词    | 问题                                                                             | 解答                                                                                                                             |
| --------- | -------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| 重新生成  | 重新生成 API 密钥后，新旧密钥是否会并存？                                        | 会，并存最长 3 天；但建议尽快完成切换                                                                                            |
| 管理维度  | 是否需要按门店分别管理 API 密钥？                                                | API 密钥按应用（屋号）维度管理。                                                                                                 |
| 私钥/公钥 | Create EasyQR code / Retrieve EasyQR code / Close EasyQR code 是否都使用“私钥”？ | Create EasyQR code / Retrieve EasyQR code / Close EasyQR code 均使用“私钥”。<br />可通过 Basic 认证或 Bearer 认证使用该私钥。    |
| 私钥/公钥 | 在 JavaScript SDK 中 new Elepay(key, options) 使用的是“公钥”吗？                 | JavaScript SDK 的 new Elepay(key, options) 中指定的 key 为“公钥”。该密钥用于前端生成支付令牌等；请使用管理后台标注为“公钥”的值。 |
