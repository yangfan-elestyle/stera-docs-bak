# API 指南

# 概述

elepay 的 API 基于 REST 构建，提供支付、退款等运营所需的多种处理能力。

# 认证

使用 API 需要注册账户并获取 API Key。Key 分为两类：测试 Key（Test key）与正式 Key（Live key）。测试 Key 仅用于测试环境（Test），正式 Key 用于生产环境（Live）。关于两种环境的详细说明见[快速开始](/get-started)。

| 序号 | 名称     | 用途                                             |
| ---- | -------- | ------------------------------------------------ |
| 1    | 测试 Key | 不会连接正式支付服务器，也不会产生真实支付记录。 |
| 2    | 正式 Key | 连接正式支付服务器（通过上线申请后可用）。       |

Publishable Key 为嵌入到应用支付页面 HTML 的公开 API Key，用于生成 Token。服务端调用 API 时，通过 HTTP Basic 认证以 Secret Key 作为用户名（密码留空）进行认证；如需使用 Bearer 认证，可用 HTTP Bearer 头替代 Basic 头。Secret Key 拥有所有 API 操作权限，请妥善保管。

| 序号 | 名称            | 用途                             |
| ---- | --------------- | -------------------------------- |
| 1    | Publishable Key | 嵌入 HTML，用于生成 Token 的公钥 |
| 2    | Secret Key      | 服务端认证用密钥                 |

> ## 📘 Basic 认证
>
> Basic 认证将用户名与密码以冒号 `:` 连接后进行 Base64 编码并发送。
>
> 1. 将 Secret Key 与空密码用冒号连接：
>    > `{SK_LIVE_KEY_HERE}:`
> 2. 对其进行 Base64 编码：
>    > `c2tfbGl2ZV94eHh4eHh4eHh4eHh4eHh4eHh4eHg6`
> 3. 将编码结果放入 HTTP Basic Authorization 头：
>    > `Authorization: Basic c2tfbGl2ZV94eHh4eHh4eHh4eHh4eHh4eHh4eHg6`

> ## 📘 Bearer 认证
>
> 若使用 Bearer 认证，请使用如下 HTTP Bearer 头：
>
> > `Authorization: Bearer {SK_LIVE_KEY_HERE}`

# 协议

出于安全考虑，与 elepay 服务器的所有 API 通讯必须使用 HTTPS。

# 方法

elepay API 请求支持 GET、POST、DELETE 三种 HTTP 方法。

# 响应格式

API 响应数据全部为 JSON 格式。

# 时间戳

与日期相关的数据以 UTC 时区的 UNIX 时间戳表示。少数不涉及秒的字段（如预计入账日、入账执行日）使用 Date 类型（例如：2023‑12‑01）。
