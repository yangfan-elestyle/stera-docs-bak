## Overview

This is a multilingual documentation site for Elepay built with Next.js 15 App Router, Fumadocs, and TypeScript. The site supports Japanese (default), English, and Chinese, serving SDK documentation for Android, iOS, JavaScript, and server-side implementations, plus OpenAPI reference docs.

## Tech Stack

- **Framework**: Next.js 15.5+ with App Router, React 19
- **Documentation**: Fumadocs (core 15.8+, mdx 12.0+, ui 15.8+, openapi 9.5+)
- **Styling**: Tailwind CSS 4 via `@tailwindcss/postcss`
- **Runtime**: Bun (package manager and runtime)
- **Search**: Orama with Japanese/Chinese tokenization
- **TypeScript**: 5.9+ with strict mode

## Development Commands

```bash
bun install                              # Install dependencies
bun run dev                              # Start dev server at http://localhost:3000
bun run build                            # Production build (auto-generates OpenAPI docs)
bun start                                # Start production server
bun run scripts/generate-openapi.ts      # Regenerate OpenAPI docs only
```

## Docker

```bash
docker build -t elepay-docs .
docker run -p 3000:3000 elepay-docs
```

Set `DOCS_BASE_URL` environment variable for external domain preview (affects OG image URLs).

## Project Structure

### Key Directories

- `app/[lang]` — Next.js App Router with dynamic language routing
  - `[lang]/(docs)/[[...slug]]/page.tsx` — MDX page renderer
  - `[lang]/layout.tsx` — Global layout with Fumadocs RootProvider
  - `[lang]/(docs)/layout.tsx` — Docs layout with DocsLayout component
  - `[lang]/og/[...slug]/route.tsx` — OG image generation
  - `api/search/route.ts` — Search API with Orama
- `content/docs` — Documentation source files (MDX + meta.json)
  - `sdks/android/` — Android SDK integration & API docs
  - `sdks/ios/` — iOS SDK integration & API docs
  - `sdks/server/` — Server-side SDK guides
  - `sdks/javascript/` — JavaScript SDK guides
  - `openapi/(generated)/` — Auto-generated OpenAPI docs (do not edit manually)
- `lib/` — Core configuration
  - `i18n.ts` — Language configuration (ja, en, zh)
  - `source.ts` — Fumadocs loader with plugins
  - `metadata.ts` — Site metadata and base URL
  - `openapi.ts` — OpenAPI configuration
- `components/` — React components
- `scripts/` — Build scripts (OpenAPI generation)
- `openapi.yaml` — OpenAPI specification source

### Generated Files (Do Not Edit)

- `.source/` — Generated by fumadocs-mdx during postinstall
- `content/docs/openapi/(generated)/` — Generated from openapi.yaml
- `.next/`, `out/` — Build artifacts
- `next-env.d.ts` — Next.js type declarations

## Multilingual Documentation

### File Naming Convention

Documentation uses language-suffixed files:

```
index.mdx       # Default Japanese (fallback when no translation exists)
meta.json       # Japanese navigation
index.en.mdx    # English translation
meta.en.json    # English navigation
index.zh.mdx    # Chinese translation
meta.zh.json    # Chinese navigation
```

### Language Configuration

Languages are defined in `lib/i18n.ts`:
- Default language: `ja` (Japanese)
- Supported languages: `ja`, `en`, `zh`
- Fallback language: `ja`
- Locale hiding: `always` (URLs use language codes)

### Important Rules

1. **Navigation sync**: When modifying `meta.json`, update ALL language versions (`meta.en.json`, `meta.zh.json`) to maintain consistent navigation structure
2. **Fallback behavior**: Missing translations automatically fall back to `index.mdx` (Japanese)
3. **Frontmatter**: Use frontmatter schema defined in `source.config.ts` for page metadata

## OpenAPI Documentation Workflow

1. Edit `openapi.yaml` at repository root
2. Run `bun run scripts/generate-openapi.ts` OR `bun run build` (includes prebuild hook)
3. Generated files appear in `content/docs/openapi/(generated)/`
4. Never edit generated files directly — they will be overwritten

The generation script (`scripts/generate-openapi.ts`):
- Deletes existing `(generated)` directory
- Uses `fumadocs-openapi` to generate pages grouped by tag
- Includes descriptions from OpenAPI spec

## Architecture Notes

### Fumadocs Integration

The documentation system uses Fumadocs with:
- **Loader** (`lib/source.ts`): Configures docs source with i18n support
- **Plugins**:
  - `lucideIconsPlugin()` — Icon support in navigation
  - `openapiPlugin()` — OpenAPI page rendering
- **MDX Components** (`mdx-components.tsx`): Custom components including `APIPage` for OpenAPI

### Page Rendering Flow

1. URL request hits `app/[lang]/(docs)/[[...slug]]/page.tsx`
2. Page extracts `[lang]` and `[[...slug]]` params
3. Loader (`source` from `lib/source.ts`) fetches corresponding MDX
4. Fumadocs renders with appropriate layout and navigation tree
5. `meta.[lang].json` provides sidebar navigation structure

### Search

Search API (`app/api/search/route.ts`) uses:
- `fumadocs-core/search` utilities
- Orama database with Japanese/Chinese tokenizers (`@orama/tokenizers`)
- Stopwords filtering (`@orama/stopwords`)

### Middleware

`middleware.ts` uses `createI18nMiddleware` from Fumadocs to:
- Handle language routing
- Exclude static assets and API routes
- Redirect based on language preference

## Common Tasks

### Adding a New Documentation Page

1. Create MDX file in appropriate directory (e.g., `content/docs/guides/new-feature.mdx`)
2. Add frontmatter with `title` and other metadata
3. Update `meta.json` to include the page in navigation
4. For multilingual: create `.en.mdx` and `.zh.mdx` variants, update corresponding meta files

### Adding a New Navigation Group

Edit the appropriate `meta.[lang].json` files following the schema in `source.config.ts`.

### Adding/Changing Languages

1. Update `lib/i18n.ts` with new language codes
2. Create corresponding `.mdx` and `meta.json` files for all pages
3. Test fallback behavior

### Customizing Theme/Styles

- Global styles: `app/global.css`
- Tailwind configuration: Built-in with v4 (no separate config needed)
- Fumadocs theme: Configured via CSS custom properties in `app/global.css`

## Build Process

1. **postinstall**: Runs `fumadocs-mdx` to generate `.source/` index
2. **prebuild**: Runs OpenAPI generation script
3. **build**: Next.js production build with standalone output
4. **Docker**: Multi-stage build using Bun base image

The `output: 'standalone'` configuration in `next.config.mjs` enables optimized Docker deployments.

## Notes for AI Agents

- Always sync ALL language versions when modifying navigation (`meta.*.json`)
- Never edit files in `content/docs/openapi/(generated)/` — regenerate instead
- Use TypeScript path aliases (`@/*`) for imports
- Respect Prettier configuration (run format before commits)
- When adding features, consider multilingual impact
